# 10. 命令与撤销重做详细需求

## 10.1 命令系统概述

### 10.1.1 命令管理器 (CommandManager)

**位置**: `packages/core/src/commands/command_manager.ts`

**核心职责**:

- 管理命令栈（撤销栈、重做栈）
- 执行命令和撤销命令
- 支持批量命令
- 提供命令状态变化事件
- 控制撤销/重做功能启用/禁用

### 10.1.2 命令接口 (ICommand)

所有命令必须实现 `ICommand` 接口：

```typescript
interface ICommand {
  desc: string; // 命令描述
  redo: () => void; // 执行命令
  undo: () => void; // 撤销命令
}
```

## 10.2 命令栈管理

### 10.2.1 命令栈结构

**撤销栈 (undoStack)**:

- 存储已执行的命令
- 后进先出 (LIFO)
- 最大长度：无限制（可配置）

**重做栈 (redoStack)**:

- 存储被撤销的命令
- 后进先出 (LIFO)
- 执行新命令时清空

### 10.2.2 命令项结构

```typescript
interface ICommandItem {
  command: ICommand; // 命令对象
  isBatched: boolean; // 是否批量命令
  hooks?: {
    // 钩子函数
    beforeUndo?: () => void;
    beforeRedo?: () => void;
  };
}
```

## 10.3 命令执行

### 10.3.1 执行命令

**流程**:

1. 创建命令对象
2. 调用 `commandManager.execute(command)`
3. 执行 `command.redo()`
4. 推入撤销栈
5. 清空重做栈
6. 触发状态变化事件

**代码示例**:

```typescript
const cmd = new AddGraphCmd([graphics]);
editor.commandManager.execute(cmd);
```

### 10.3.2 批量命令

**用途**: 将多个命令组合成一个命令单元

**实现**: `MacroCmd` 类

**特性**:

- 多个命令作为一个整体
- 撤销时按相反顺序撤销所有命令
- 重做时按顺序重做所有命令

**标记**: `isBatched: true`

**使用场景**:

- 创建图形时同时更新父容器大小
- 对齐操作涉及多个图形移动
- 编组操作涉及多个操作

### 10.3.3 事务 (Transaction)

**位置**: `packages/core/src/transaction.ts`

**用途**: 将多个操作组合成一个命令

**特性**:

- 记录操作前的状态
- 记录操作后的状态
- 自动生成撤销/重做命令

**使用场景**:

- 批量更新图形属性
- 复杂操作（如编组、对齐）

## 10.4 撤销操作

### 10.4.1 撤销流程

1. 检查撤销栈是否为空
2. 从撤销栈弹出命令
3. 如果是批量命令，弹出所有批量命令
4. 调用 `command.undo()`
5. 推入重做栈
6. 触发状态变化事件
7. 重新渲染

### 10.4.2 撤销限制

**限制条件**:

- 撤销栈为空时无法撤销
- 撤销/重做功能被禁用时无法撤销
- 某些特殊状态下可能禁用撤销

### 10.4.3 批量撤销

**处理方式**:

- 如果命令标记为 `isBatched`
- 撤销时撤销所有连续的批量命令
- 按相反顺序撤销

## 10.5 重做操作

### 10.5.1 重做流程

1. 检查重做栈是否为空
2. 从重做栈弹出命令
3. 如果是批量命令，弹出所有批量命令
4. 调用 `command.redo()`
5. 推入撤销栈
6. 触发状态变化事件
7. 重新渲染

### 10.5.2 重做限制

**限制条件**:

- 重做栈为空时无法重做
- 执行新命令后清空重做栈
- 撤销/重做功能被禁用时无法重做

## 10.6 命令类型

### 10.6.1 添加图形命令 (AddGraphCmd)

**位置**: `packages/core/src/commands/add_graphs.ts`

**功能**: 添加图形到场景图

**撤销**: 从场景图移除图形

**重做**: 将图形添加回场景图

### 10.6.2 更新图形属性命令 (UpdateGraphicsAttrsCmd)

**位置**: `packages/core/src/commands/update_graphics_attrs_cmd.ts`

**功能**: 更新图形属性

**撤销**: 恢复旧属性值

**重做**: 应用新属性值

**特性**:

- 记录属性变化前后的值
- 只更新变化的属性

### 10.6.3 设置元素属性命令 (SetGraphsAttrsCmd)

**位置**: `packages/core/src/commands/set_elements_attrs.ts`

**功能**: 批量设置多个图形的属性

**撤销**: 恢复所有图形的旧属性

**重做**: 应用所有图形的新属性

### 10.6.4 重新父级命令 (ReparentCmd)

**位置**: `packages/core/src/commands/reparent.ts`

**功能**: 改变图形的父容器

**撤销**: 恢复原来的父容器

**重做**: 应用到新的父容器

### 10.6.5 宏命令 (MacroCmd)

**位置**: `packages/core/src/commands/macro.ts`

**功能**: 组合多个命令

**撤销**: 按相反顺序撤销所有命令

**重做**: 按顺序执行所有命令

## 10.8 命令状态管理

### 10.8.1 启用/禁用

**启用撤销/重做**:

```typescript
editor.commandManager.enableRedoUndo();
```

**禁用撤销/重做**:

```typescript
editor.commandManager.disableRedoUndo();
```

**使用场景**:

- 某些操作（如导入）可能需要禁用撤销
- 某些特殊模式下禁用撤销

### 10.8.2 状态事件

**事件类型**: `change`

**触发时机**:

- 执行命令后
- 撤销命令后
- 重做命令后

**用途**:

- 更新 UI（撤销/重做按钮状态）
- 自动保存触发

## 10.10 命令最佳实践

### 10.10.1 命令设计原则

1. **原子性**: 每个命令应该是原子操作
2. **可逆性**: 每个命令都应该可以完全撤销
3. **描述性**: 命令描述应该清晰明了
4. **性能**: 命令执行应该高效

### 10.10.2 命令组合

**何时使用批量命令**:

- 多个相关操作应该作为一个整体
- 用户的一次操作可能产生多个命令
- 需要保持数据一致性

**何时使用事务**:

- 复杂的批量操作
- 需要记录操作前后状态
- 需要自动生成撤销/重做命令

## 10.11 命令系统扩展

### 10.11.1 创建新命令

**步骤**:

1. 实现 `ICommand` 接口
2. 实现 `redo()` 方法
3. 实现 `undo()` 方法
4. 提供清晰的描述

**示例**:

```typescript
class MyCommand implements ICommand {
  desc = 'My Command';

  constructor(private editor: SuikaEditor) {}

  redo() {
    // 执行操作
  }

  undo() {
    // 撤销操作
  }
}
```

### 10.11.2 命令钩子

**用途**: 在命令执行前后执行额外操作

**钩子类型**:

- `beforeUndo`: 撤销前执行
- `beforeRedo`: 重做前执行

**使用场景**:

- 清理临时状态
- 更新缓存
- 触发额外事件

## 10.12 命令系统性能

### 10.12.1 内存管理

**优化策略**:

- 限制命令栈大小（可选）
- 定期清理旧命令（可选）
- 使用弱引用（未来优化）

### 10.12.2 执行性能

**优化策略**:

- 批量命令合并
- 延迟渲染
- 增量更新

## 10.13 命令系统与自动保存

### 10.13.1 自动保存触发

**位置**: `apps/suika/src/store/auto-save-graphs.ts`

**机制**:

- 监听命令管理器 `change` 事件
- 使用防抖 (debounce) 延迟保存
- 保存到 localStorage

**防抖时间**: 10ms

### 10.13.2 保存内容

**保存格式**: JSON

**保存内容**:

- 应用版本
- 图纸 ID
- 图形数据

**存储键**: `suika-paper`
