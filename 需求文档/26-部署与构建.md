# 26. 部署与构建

## 26.1 构建系统概述

### 26.1.1 Monorepo 架构

**包管理器**: PNPM Workspace

**工作区配置**:

```yaml
# pnpm-workspace.yaml
packages:
  - 'packages/*'
  - 'apps/*'
```

**依赖管理**:

- 共享依赖提升到根目录
- 包间依赖使用 workspace: 协议
- 自动依赖解析和链接

### 26.1.2 构建工具链

**Vite**: 前端构建工具

- 快速冷启动
- 热更新 (HMR)
- 优化的生产构建

**esbuild**: 快速打包器

- Go 语言编写，性能极高
- 支持 TypeScript 编译
- 集成到 Vite 构建流程

**TypeScript**: 类型检查

- 编译时类型检查
- 生成类型定义文件
- 开发时错误提示

## 26.2 开发环境构建

### 26.2.1 单用户版开发

**启动命令**:

```bash
# 安装依赖
pnpm install

# 启动单用户版开发服务器
pnpm run dev
```

**开发服务器配置**:

- 端口: 5173 (Vite 默认)
- 热重载: 自动检测文件变化
- CORS: 开发时允许跨域

### 26.2.2 多人协作版开发

**启动命令**:

```bash
# 启动多人协作版开发服务器
pnpm run dev-m
```

**开发服务器特点**:

- 同时启动前端和模拟后端
- WebSocket 连接用于协作
- 热重载支持协作状态

### 26.2.3 包级开发

**单独开发包**:

```bash
# 开发 core 包
pnpm run core:dev

# 开发 components 包
pnpm run components:dev
```

**包间依赖**:

- 使用 `workspace:*` 引用
- 自动检测依赖变化
- 实时更新依赖包

## 26.5 Docker 部署

### 26.5.1 Dockerfile

**多阶段构建**:

```dockerfile
# 构建阶段
FROM node:18-alpine AS builder

WORKDIR /app

# 复制包管理文件
COPY pnpm-lock.yaml ./
COPY package.json ./

# 安装依赖
RUN npm install -g pnpm
RUN pnpm install --frozen-lockfile

# 复制源代码
COPY . .

# 构建应用
RUN pnpm build

# 生产阶段
FROM nginx:alpine

# 复制构建产物
COPY --from=builder /app/apps/suika/build /usr/share/nginx/html

# 复制 Nginx 配置
COPY nginx/nginx.conf /etc/nginx/nginx.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### 26.5.2 Nginx 配置

**nginx.conf**:

```nginx
events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    # 日志格式
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;

    # 基本设置
    sendfile        on;
    tcp_nopush      on;
    tcp_nodelay     on;
    keepalive_timeout 65;
    types_hash_max_size 2048;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types
        text/plain
        text/css
        text/xml
        text/javascript
        application/javascript
        application/xml+rss
        application/json;

    server {
        listen       80;
        server_name  localhost;
        root         /usr/share/nginx/html;
        index        index.html;

        # 安全头
        add_header X-Frame-Options "SAMEORIGIN" always;
        add_header X-XSS-Protection "1; mode=block" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header Referrer-Policy "no-referrer-when-downgrade" always;
        add_header Content-Security-Policy "default-src 'self' http: https: data: blob: 'unsafe-inline'" always;

        # SPA 路由处理
        location / {
            try_files $uri $uri/ /index.html;
        }

        # 静态资源缓存
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
        }

        # API 代理 (如果需要)
        location /api/ {
            proxy_pass http://backend:3000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
}
```

## 26.8 CI/CD 流程

### 26.8.1 GitHub Actions

**构建工作流**:

```yaml
# .github/workflows/build.yml
name: Build and Deploy

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Setup Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '18'
        cache: 'pnpm'
    
    - name: Install dependencies
      run: pnpm install --frozen-lockfile
    
    - name: Type check
      run: pnpm run type-check
    
    - name: Lint
      run: pnpm run lint
    
    - name: Test
      run: pnpm run test
    
    - name: Build
      run: pnpm build
    
    - name: Deploy to Vercel
      if: github.ref == 'refs/heads/main'
      run: |
        npm i -g vercel
        vercel --prod --yes
```

## 26.10 备份和恢复

### 26.10.1 数据备份

**自动备份**:

```bash
# 数据库备份脚本
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
pg_dump -h localhost -U suika suika > backup_$DATE.sql

# 文件备份
tar -czf uploads_$DATE.tar.gz uploads/
```

### 26.10.2 备份策略

**备份频率**:

- 数据库: 每日全量 + 每小时增量
- 文件: 每日备份
- 配置: 每次部署备份

**保留策略**:

- 日备份: 7天
- 周备份: 4周
- 月备份: 12个月

### 26.10.3 灾难恢复

**恢复流程**:

1. 停止应用服务
2. 恢复数据库
3. 恢复文件
4. 启动应用服务
5. 验证数据完整性

const loadFromCDN = (url: string) => {
  return new Promise((resolve, reject) => {
    const script = document.createElement('script');

## 26.12 版本发布

### 26.12.1 版本管理

**语义化版本**:

- 主版本: 不兼容的 API 更改
- 次版本: 向后兼容的功能新增
- 修订版本: 向后兼容的 bug 修复

**版本号格式**: `MAJOR.MINOR.PATCH`

### 26.12.2 发布流程

**发布步骤**:

1. 更新版本号
2. 更新 CHANGELOG
3. 创建 Git 标签
4. 构建发布版本
5. 部署到生产环境
6. 通知用户

### 26.12.3 回滚策略

**快速回滚**:

```bash
# 回滚到上一个版本
git checkout v1.0.1
docker-compose up --build
```

**灰度发布**:

- 新版本逐步放量
- 监控关键指标
- 异常时快速回滚
